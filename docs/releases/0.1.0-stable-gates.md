Post-publication checksum and byte-identity rows cannot become complete before
publication. `WORKFLOW_ENFORCED` is accepted only for those two rows because the
workflow performs both checks immediately after creating the release. Record the
actual results after publication; do not mark either result complete early.

## Packwiz candidate evidence

The pre-publication `packwiz-candidate-smoke` gate may be completed by either:

1. **Completed:** publish `v0.1.0-rc.1` as a prerelease, run `packwiz url add` and
   `packwiz refresh` against its immutable public JAR URL, verifying the URL,
   hash format, non-empty hash, and JAR structure, and confirming that the RC
   used the same generic naming logic as stable. See the
   [RC publication record](0.1.0-rc.1-publication.md); or
2. serving the final stable candidate JAR from a disposable local HTTP server,
   running `packwiz url add` and `packwiz refresh`, and verifying the generated
   URL, hash format, non-empty hash, and JAR structure.

The gate does not require the final stable GitHub Release or its assets to exist.

## Post-Publication Packwiz Verification

Status: **NOT PERFORMED**. This is not a pre-publication gate and is not
`WORKFLOW_ENFORCED`.

After `v0.1.0` is published:

1. Run `packwiz url add` against the published Stable JAR URL documented in
   [`0.1.0.md`](0.1.0.md).
2. Verify the generated URL, hash format, and non-empty hash.
3. Run `packwiz refresh` and confirm that it preserves the stable URL.
4. Record the result and JAR-structure checks in the stable publication record.
