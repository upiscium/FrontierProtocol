# 0.1.0 Stable Release Gates

This offline ledger is the publication contract for `v0.1.0`. `COMPLETE` means
retained evidence exists for the final stable candidate, not merely an earlier
alpha. The release workflow runs `verifyStableReleaseGates` before stable
publication and refuses publication while any required row is `INCOMPLETE`.

| Gate ID | Required | Status | Evidence required |
| --- | --- | --- | --- |
| unit-tests | yes | INCOMPLETE | Passing final-candidate unit tests |
| asset-tests | yes | INCOMPLETE | Passing final-candidate asset tests |
| clean-datagen | yes | INCOMPLETE | `runData` plus clean generated-resource status |
| clean-build | yes | INCOMPLETE | Passing `clean build` |
| all-gametests | yes | INCOMPLETE | All required GameTests pass |
| dedicated-server-smoke | yes | INCOMPLETE | Final candidate reaches `Done` and stops cleanly |
| stable-candidate | yes | INCOMPLETE | `verifyReleaseCandidate -PreleaseStatus=public_stable_release` |
| fresh-world-smoke | yes | INCOMPLETE | Retained fresh-world startup and initial-center evidence |
| alpha1-world-upgrade | yes | INCOMPLETE | Backup-copy upgrade, save, reload, inventory, state, and cleanup evidence |
| english-graphical-smoke | yes | INCOMPLETE | Final-candidate in-world English verification |
| japanese-graphical-smoke | yes | INCOMPLETE | Final-candidate in-world Japanese verification |
| packwiz-smoke | yes | INCOMPLETE | Final public stable URL add and refresh |
| published-checksum | yes | WORKFLOW_ENFORCED | Anonymous published SHA-256 verification immediately after creation |
| published-byte-identity | yes | WORKFLOW_ENFORCED | Published JAR equals verified candidate bytes immediately after creation |
| support-contract | yes | COMPLETE | `docs/stable-readiness-0.1.0.md` |
| known-issues | yes | COMPLETE | `docs/releases/0.1.0-known-issues.md` |
| changelog | yes | INCOMPLETE | Frozen `0.1.0` changelog entry |
| stable-release-notes | yes | INCOMPLETE | Frozen `docs/releases/0.1.0.md` |
| license-provenance | yes | INCOMPLETE | Final candidate license/provenance verification |

Post-publication checksum and byte-identity rows cannot become complete before
publication. `WORKFLOW_ENFORCED` is accepted only for those two rows because the
workflow performs both checks immediately after creating the release. Record the
actual results after publication; do not mark either result complete early.
